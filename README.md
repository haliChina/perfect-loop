## ⚠️ 请注意，先看这里

这是一个**恶作剧/压测性质的脚本（PoC 类似物）**，不是利用框架。它针对一类“玩家答题 → 成绩上榜”的
公开答题应用（示例端点为一个朋友的小站），验证的是这类站点的一个通病：

> **上榜接口 `POST /quizzes/{id}/players` 对访客开放、无任何频控/人机验证/满分合理性校验 ——**
> 脚本可以直接读回题库的正确答案（响应里带 `correct` 标记），然后以任意玩家名把满分成绩
> 无限刷上榜单。

脚本本身不做任何超出“写榜”的事情：不读取他人数据、不导出凭证、不做持久化后门。
自建一棵树之后，还可以用属主权限一键把自己刷的玩家**全部清掉**——这是本工具与“纯捣乱脚本”
的区别：**自己造的榜，自己能收拾干净**。

- 目标站点是朋友的（已知情）；工具默认打本地 mock，**必须显式加 `--live` 才打线上**
- **不预置任何具体目标**：除了这个示例域名外，所有端点都由命令行显式提供
- 已实测：满分可稳定上榜，`--count 0 --interval 0` 长时间连发无失败
- 与该站点运营方无冲突；若你是同类站点的维护者，可直接参考[给运营者的修复清单](#给运营者的修复清单)

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 循环拉取题库 → 读出正确答案 → 满分提交上榜 | 不破解账号、不碰他人数据 |
| 随机生成 5–15 字“奇葩玩家名”占榜 | 不做 XSS/注入/任何注入类攻击 |
| `--auto-tree` 自建一棵树拿属主 User-Key | User-Key 只用于**自己树上的**属主动作（删玩家/查榜） |
| `--cleanup` 一键清掉自己刷的前缀玩家 | 不提供清理**别人**树的任何能力 |
| 断线自动重连、419/429 自愈、批次重建会话 | 不是分布式压测工具，单进程单会话 |

## 工作原理（三行版）

1. `GET /quizzes/{id}/round` 返回的题目选项里直接带 `correct: true` 标记 —— 满分答案是“读”出来的，不是“猜”出来的；
2. `POST /quizzes/{id}/players` 是访客入场接口，不需要属主 User-Key，也不校验提交频率 —— 于是可以循环提交；
3. 属主 User-Key 只有一个来源：`POST /quizzes` 的响应，所以“自动拿 key”等价于“自动建一棵自己的树”。

## 快速开始

```bash
pip install requests

# ① 本地 mock 里先跑通（默认端点就是 mock，不需要 --live）
python perfect_loop.py --auto-tree --creator 测试树

# ② 对自己拥有的线上树连发满分
python perfect_loop.py --live --quiz <你的quizId> --allow-public --interval 0 --count 0

# ③ 查榜（公开接口，无需 key）
python perfect_loop.py --live --quiz <quizId> --verify

# ④ 清理：删掉所有前缀匹配的玩家（属主动作，需要该树的 userKey）
python perfect_loop.py --live --quiz <quizId> --user-key <key> --cleanup
```

## 参数一览

| 参数 | 说明 | 默认 |
|---|---|---|
| `--base` | 自定义端点（不打示例站时用） | `http://127.0.0.1:8899/tree/api` |
| `--live` | 打示例线上端点（必须显式指定） | 关 |
| `--quiz <id>` | 目标树 id | — |
| `--auto-tree` | 自动建一棵自己的树并取属主 User-Key | 关 |
| `--creator` | 建树时的树主名 | `loop` |
| `--user-key` | 已有的属主 User-Key（或从 `creds.json` 自动载入） | — |
| `--allow-public` | 允许往非自有的树提交（等同访客正常答题上榜） | 关 |
| `--prefix` | 玩家名前缀（用于识别与清理） | `孙笑川_` |
| `--interval` | 每次提交间隔（秒，`0` = 全速） | `5.0` |
| `--count` | 总提交数（`0` = 无限） | `0` |
| `--jitter` | 间隔随机抖动 | `0.4` |
| `--burst N` | 每 N 轮重建全新 HTTP 会话（0 = 不重连） | `10` |
| `--rest` | 已废弃，保留仅为兼容旧命令行，被忽略 | — |
| `--verify` | 打印榜单后退出 | 关 |
| `--cleanup` | 删除前缀匹配的玩家后退出（属主动作） | 关 |
| `--locale` | 题库语言 | `cn` |

## 实测记录

- 环境示例站（朋友自建，已知情）+ 本地 mock
- `--auto-tree` 一键建树取 key：成功，key 已自动存入 `creds.json`
- `--interval 0 --count 0` 连发：长时间运行，满分提交稳定上榜，无失败样本
- `--cleanup`：前缀玩家全部删除，榜单恢复原状
- 玩家名生成：`孙笑川_` 前缀 + 4–11 位随机小写/数字，总长不超过服务端 nameMax=15

## 给运营者的修复清单

如果你运营同类站点，按性价比排序：

1. **选项别带答案下发** —— `correct` 标记只应在判分服务端使用，绝不能出现在 `GET /round` 响应里。这是本脚本成立的根本原因；
2. **上榜接口加频控** —— 按来源 IP + quiz 维度限流（如 1 req/5s），配合 429 + Retry-After；
3. **满分合理性校验** —— 短时间内同一 IP 的大量满分提交、玩家名前缀聚集，直接风控标记；
4. **提交接口加人机验证** —— PoW（如 [Cap](https://github.com/tiagozip/cap)）或服务端一次性 ticket；
5. **submissionId 幂等去重** —— 服务端应按 `submissionId` 去重，而不是依赖客户端生成唯一值；
6. **属主凭证单独发放** —— User-Key 走邮件/后台下发，而不是“谁建树谁拿 key”，避免无限小号建树。
